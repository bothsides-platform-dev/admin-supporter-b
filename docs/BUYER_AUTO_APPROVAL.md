# 신규사업체 구매사 자동 승인 표시

공유 DB 마이그레이션의 소유자는 `bidit` 저장소다. 미적용된 `bidit/scripts/migrations/20261020-buyer-auto-approval.sql`과 `20261025-new-business-approval.sql` 실행·커밋 → 관리자 서비스 → 구매사 서비스 순서로 배포한다. 새 DB 필드는 추가하지 않고 기존 감사 테이블을 사용한다. 운영 상세는 `bidit/docs/BUYER_AUTO_APPROVAL.md`를 따른다.

신규 자동 승인은 APICK 개업일·대표명을 국세청으로 검증한 개업 6개월 미만 구매사에만 적용한다. 보나페이 조회·판정은 제거했다. `new_business_exception`은 **신규사업체 예외**로 표시하며 과거 `api_confirmed`의 **자동 확인** 표시와 감사 이력은 유지한다. 승인 신청은 `approved` 필터에서 찾고 심사 대기 목록에서는 제외한다.

처리 이력은 기존 신청 ID 기준 `admin_audit_logs` 조회를 사용한다. `workspace.auto_approve` 사건의 **자동 승인 완료**에서 신규사업체는 검증된 개업일·국세청 확인·개업 6개월 미만 판정을 표시한다. 과거 보나페이 사건의 적용 기준일과 영세 판정은 그대로 보존한다. 수동 승인은 기존대로 동작한다.

APICK 성공·번호 일치 원본 JSON 전체(`api`·`data`, 대표명 포함)는 승인 여부와 무관하게 신청에 연결된 별도 `workspace.apick_lookup` 사건의 `payload_json.after.response`에 저장한다. 관리자는 이 조회 원본을 별도 조회 이력에서 확인한다. 조회 성공은 자동 승인 자체를 뜻하지 않는다. 키·요청 헤더·국세청 원문은 저장하지 않으며 원본을 일반 구매사·PG 응답이나 운영 알림에 전달하지 않는다.

자동 승인을 중지하려면 구매사 서버의 `APICK_API_KEY`를 제거하고 재시작한다. 관리자 앱에는 이 키가 필요하지 않다. 기존 승인 이력·출처 enum은 보존하고 과거 신청을 재심사 대기로 일괄 변경하지 않는다. 미인증 재가입 정리는 신규 APICK 승인과 과거 보나페이 승인의 정확한 출처 조합 모두에 기존 보호 조건을 적용한다.
