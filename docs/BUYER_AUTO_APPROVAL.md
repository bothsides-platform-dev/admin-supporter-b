# 영세 확인 구매사 자동 승인 표시

공유 DB 마이그레이션의 소유자는 `bidit` 저장소다. 배포는 `bidit/scripts/migrations/20261020-buyer-auto-approval.sql`과 `20261025-new-business-approval.sql` 실행·커밋 → 관리자 서비스 → 구매사 서비스 순서다. 구매사 서비스 배포부터 별도 활성화 플래그 없이 신규 구매사 조회·판정을 실행한다. 운영 확인 과제·외부 응답 실측 기록은 `bidit/docs/BUYER_AUTO_APPROVAL.md`를 따른다.

관리자는 `api_confirmed`를 **자동 확인**, `new_business_exception`을 **신규사업체 예외**로 읽는다. 신규사업체 예외는 구매사 서버가 APICK 개업일·대표명을 국세청으로 검증하고 개업 6개월 미만인 경우 적용한 내부 정책이다. 자동 승인 신청은 기존 `approved` 상태이므로 승인 필터에서 조회하고 심사 대기 필터와 다음 대기 건에서는 제외한다.

처리 이력은 기존 신청 ID 기준 `admin_audit_logs` 조회를 사용한다. `workspace.auto_approve` 사건은 **자동 승인 완료**와 공급자·사업자번호·조회 시각·적용 기준일·영세 판정을 표시한다. 신규사업체 사건은 적용 기준일 대신 검증된 개업일과 국세청 개업일 진위 확인, 개업 6개월 미만 예외 판정을 표시한다. 사람의 수동 승인은 기존대로 동작한다.

보나페이 자동 승인은 환경변수로 중지할 수 없다. 신규사업체 예외만 중지하려면 구매사 서버의 `APICK_API_KEY`를 제거하고 재시작한다. 이 키는 관리자 앱에 필요하지 않다. 중지가 필요하면 구매사 자동 승인 코드 변경을 되돌려 재배포하며 기존 승인 이력은 유지한다. 출처 enum을 삭제하거나 과거 신청을 재심사 대기로 일괄 변경하지 않는다.
